# 预览常驻服务模板

两份 `.service.example` 为准备文件，尚未安装或启动。仅使用已审查的 activation_cli；不传 --execute，不创建 approval.json。它们仍可写入预览 journal 和事件账本，因此启动前需记录原数据基线。

私有配置及 receiver.env 需要用户授权后创建，目录 0700、文件 0600，不写入仓库。EnvironmentFile 中 PROLIFIC_HOOK_SECRET 仅存签名密钥；CLI 当前会将其展开为进程参数，因此不得输出或收集该服务的完整进程参数。API token 和完成 URL 只放私有 JSON。

接收器仅监听 127.0.0.1:8013。拟使用独立 HTTPS 端口/入口，不修改现有 tailnet-only 根服务的公开范围。公网入口尚未配置，不声明 Prolific 能送达。

调度间隔 300 秒是每次完成后等待时间，并非保证五分钟内完成全研究对账。现有完整逐条对账可能需要约二十分钟；上线前还需检验 webhook 响应时延和持久重试，不能用已启动服务代替该证据。

启用前检查：修复分支通过双轴审查、私有配置权限、聊天覆盖证明及有效期、原数据 hash、签名错误拒绝、真实事件接收、持久重启、历史记录预览无自动动作。最后仍须用户确认历史操作名单和实际启用范围。
