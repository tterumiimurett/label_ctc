# 06: 典型缺失结果自动请求退回，例外进入人工队列

**Status:** Implemented, independently reviewed and merged (86cec8f); production not activated

**Publication label:** ready-for-agent

**Blocked by:** 05 — 确认缺失后生成唯一待联系请求。

**What to build:** 研究者批准规则并完成上线验收后，符合条件的新案例无需逐session人工审批，自动发送一次已确认文案；例外在本地持久队列等待人工处理。历史积压名单仍单独批准。

- [ ] 保留全部AW检查、十分钟等待、发送前每位最新平台/本地复查及三字段身份一致性；常规新案例通过规则可自动执行，不要求操作者手工列出每个approved_session。
- [ ] 聊天侧：完整、可访问历史为空允许自动；研究者最后发言后没有参与者新回复允许自动；有参与者新回复待处理则转人工不发。只有参与者发言而无研究者回应也属于待处理回复。不要求消息包含Session ID，不用LLM推断；时间/方向/历史覆盖不明或读取失败转人工。
- [ ] 同session已发退回请求/有不可逆发送尝试，不再自动POST。明确已联系案例进入本地人工队列，并保留不可逆发送记录；没有新回复仅表示不因聊天时间线阻止，不能绕过每session一次。
- [ ] 对已发现的缺失待联系案例，答案随后到达或发现已联系，先不发送并转人工确认，不静默结束；不要把所有正常成功提交都塞入人工队列。
- [ ] 草稿、归档/其他session答案、身份错配、保存/读取故障等转人工。特殊情况不自动套用退回文案，记录原因、证据和拟处理建议，允许查看；不要求新增外部通知服务。
- [ ] 采用单一普通消息操作和已确认文案；发送成功不代表RETURNED，不释放名额或修改审核/支付状态。
- [ ] 与Ticket05共用锁和不可逆attempt屏障；候选重建、重启、并发或state变化不能重新允许发送。不确定交付先查证，无法确认进人工，绝不盲重试。
- [ ] 隔离验证真实适配器/受控HTTP全链路，提供具体人工核验材料；生产默认关闭，启用仍须确认，历史名单批准独立于常规规则。

文案沿用spec已批准文本。聊天规则按完整参与者消息时间线及最后研究者发言判断，不将缺少Session ID解释为无关。

## 本轮人工确认与复核决定（2026-09-10）

用户经 Grill Me 确认本票修订规则。对应实现 Agent 与独立双轴 Code Review Agent 必须收到这些修改意见，并依据更新后的 Ticket/spec 审查。

修改、必要测试、双轴审查及问题修复复审完成后，若没有需要人工核验的事项，可以自动合并并继续已授权流程；若审查判断需要人工核验，暂停相关合并和依赖步骤，展示具体问题、证据及对应版本，等待用户核验。审查报告须说明是否存在人工事项及理由；不得用测试通过替代尚未完成的明确人工要求。

本决定不授权生产执行。详细交接和恢复按 [通用人工核验流程](../human-review-protocol.md) 执行。
