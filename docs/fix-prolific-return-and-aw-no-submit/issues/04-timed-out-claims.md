# 04: 超时结果独立归档并释放名额

**Status:** Revised after human review 2026-09-10 — implementation/re-review required

**Publication label:** ready-for-agent

**Blocked by:** 03 — 已退回 session 归档并释放名额。

**What to build:** 经当前平台状态和三字段身份核对确认 TIMED-OUT 后，采用与 RETURNED 相同的安全归档/释放机制，但独立记录超时原因和目录。

- [ ] 有最终答案则保留原始字节、哈希、原分配和审计证据，归档至 `excluded_submissions/YYYY-MM-DD/prolific_timed_out/`，退出正式计数并释放名额；无答案只释放占位，不制造答案文件。
- [ ] 不将超时误标为 RETURNED；身份错配、读取故障、归档冲突、显式撤回同意或不兼容状态反转仍转人工。
- [ ] 共用可靠锁和恢复机制；中断/重复处理只生效一次；旧 session 不得重新领取、保存草稿或迟交使结果重新计数。
- [ ] 隔离演示有/无答案超时、正确新分配、原字节保全、逐阶段故障恢复及超时/退回各自目录和状态隔离。
- [ ] 本研究最大允许时间为研究者确认的14分钟；以平台当前 TIMED-OUT 状态为触发依据，不用本地14分钟计时器猜平台状态。
- [ ] 默认不执行生产迁移或发布；修订后代码复审及所需人工核验完成前不合并，不启动下一轮。

本次规则替代旧版“超时有答案一律留在正式目录并转人工”。不修改平台审核、支付或提交状态。

## 本轮人工确认与复核决定（2026-09-10）

用户经 Grill Me 确认本票修订规则。对应实现 Agent 与独立双轴 Code Review Agent 必须收到这些修改意见，并依据更新后的 Ticket/spec 审查。

修改、必要测试、双轴审查及问题修复复审完成后，若没有需要人工核验的事项，可以自动合并并继续已授权流程；若审查判断需要人工核验，暂停相关合并和依赖步骤，展示具体问题、证据及对应版本，等待用户核验。审查报告须说明是否存在人工事项及理由；不得用测试通过替代尚未完成的明确人工要求。

本决定不授权生产执行。详细交接和恢复按 [通用人工核验流程](../human-review-protocol.md) 执行。
