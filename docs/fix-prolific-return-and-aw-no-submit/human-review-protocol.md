# 人工意见确认、审查交接与恢复流程

2026-09-10。通用流程；各票本轮复核决定记录在对应 Ticket。

人工核验无需修改且用户明确通过时，继续已授权后续流程，无需用户另说“继续”。用户提出修改意见时，必须先使用 Grill Me 确认理解：明确修改内容、边界、验收标准，并且必须直接询问“修改完成后是否需要再次人工核验”，由用户决定并记录。用户确认共同理解后才按该意见修改；不得自行推断免除复核或默认每次都要复核。该问题未回答时，不得视为已完成确认。

修改后执行必要测试和 code-review 双轴独立审查，修复并复审。用户要求再次人工核验时，展示修改证据并等待明确通过；用户明确无需再次人工核验时，在约定验收及审查通过后继续。若出现新决策、歧义或超出已确认范围，重新 Grill Me，不能沿用旧批准扩大范围。“收到”“明白”等不代表核验通过。

用户在其他独立任务中核验后，会告知协调任务。协调任务读取对应聊天记录及提交，核对通过或修改意见、适用范围、对应版本以及再次人工核验的决定。信息缺失或不明确时向用户确认；不得仅凭存在提交、分支或另一任务声称完成就认定通过。

每次暂停应记录待核验事项、证据和版本、所需用户决定以及通过后的继续位置；恢复从该位置继续，不跳过未完成门槛。若应用内 goal 的恢复需要用户操作，应如实说明，不声称已经恢复。

修改意见必须同步到对应 Ticket 的实现 Agent、Ticket/spec 及独立双轴 Code Review Agent。审查交接必须包含用户确认的修改意见及验收要求；审查以更新后的要求为准，不能只对照旧版 Ticket。审查报告明确记录是否存在需要人工核验的事项及理由，不能仅以测试通过推断不存在人工事项。
